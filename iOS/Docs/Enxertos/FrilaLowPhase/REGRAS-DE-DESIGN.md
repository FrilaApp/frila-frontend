## 2. Diretriz inegociável: implementação 100% nativa

O Frila é um ecossistema **Swift nativo** (SwiftUI, iOS 26+ com suporte a macOS 14+). É proibido implementar o app, o protótipo do simulador ou qualquer componente em HTML, CSS, JavaScript ou qualquer stack web, e proibido usar servidor local ou harness web para construir ou validar.

Tudo que roda (Design Lab, protótipo do simulador, bancada de testes, componentes) vive em `Sources/FrilaDesignSystem/` ou `FrilaApp/` e é validado por `#Preview`, pelo Design Lab e pelo simulador.

**Única exceção:** `docs/prototype/` é um espelho somente leitura do canvas do claude.ai (`.dc.html`). Serve como especificação de fluxo e copy. Nunca é executado, estendido ou importado por código Swift, e nenhum arquivo web novo é criado em outro lugar. O Protótipo Web (canvas) e o App (SwiftUI) são frentes separadas: não se misturam em relatórios, branches ou commits.


## 1. Critical Restrictions & Inviolable Guardrails (Zero Slop)

| # | Guardrail | Inviolable Rule | Common Forbidden Violation |
| :--- | :--- | :--- | :--- |
| **G1** | **Native-Only Implementation** | Frila is **100% Native Swift / SwiftUI**. Implementing the app, its simulator prototype, or any component with `.html`, `.css`, `.js`, Node servers, or web harnesses is strictly forbidden. All runnable prototyping lives in `Sources/FrilaDesignSystem/DesignLab/` (`System/`, `Experiments/`) and `FrilaApp/FrilaApp/` (`SimulatorRootView`, `Prototype/`). Single exception: `docs/prototype/` is a read-only mirror of the claude.ai design canvas (`.dc.html`), used as flow and copy specification and never executed or imported. | Creating HTML/JS mockups or web harnesses to test UI layouts. Adding web files outside `docs/prototype/`. |
| **G2** | **Zero Web Drop-Shadows** | Card surfaces embody an *Achromatic Museum Wall* aesthetic (`#FFFFFF` Light / `#090908` Dark). Cards have zero black diffuse CSS shadows (`box-shadow`). Depth is achieved through material elevation, rim highlights, and pure alpha media outlines. | Adding `.shadow(color: .black.opacity(0.15), radius: 20, y: 10)` to canonical cards. |
| **G3** | **Zero Emojis in UI** | Status chips, badges, buttons, and indicators strictly consume **native SF Symbols** (`Image(systemName:)`). | Using emojis or decorative text glyphs (`🛡️`, `⏳`, `●`, `★`, `✓`) as visual icons. |
| **G4** | **Zero `.italic()`** | Typography follows the upright *Museum Placard* convention. None of the 5 paradigms (Swiss, Curatorial, Humanist, Archival, Glass) admits italics for titles or labels. | Calling `.italic()` on any typography modifier. |
| **G5** | **Shielded Currency & Rates** | Financial formatting is strictly handled via `FrilaMoney` (fixed `en_US` locale, USD, `$140/hr`, `Est. $33,600`) and rendered via `FrilaPriceTag`. Spoken VoiceOver labels are mandatory. | Interpolating string literals like `Text("$\(rate)/hr")` (produces `LocalizedStringKey` and device locale corruption). |
| **G6** | **100% Round Pill Buttons (`Capsule`)** | All buttons across the design system are strictly **100% Round Pills (`Capsule()`, 9999px)**. Heights are standardized to 32pt (compact), 44pt (standard), and 52pt (prominent). | Deforming buttons into rounded rectangles ($R=12$) or squircles. |
| **G7** | **Concentric Mathematical Law** | Container corner radii and inner elements must strictly satisfy: $\mathbf{R_{\text{outer}} = R_{\text{inner}} + \text{Padding}}$. | Inner radius greater than outer ($R_{inner} > R_{outer}$) causing visual pinching. |
| **G8** | **Apple HIG Minimum Touch Target** | Every interactive element must satisfy Apple's minimum touch hitbox: $\ge \mathbf{44 \times 44\text{pt}}$ (enforced via `.frilaHitbox()`). | Buttons or touch areas smaller than 44pt without hitbox compensation. |
| **G9** | **Absolute Secrets Protection** | Forbidden to commit `.env` files, API keys, credentials, or authentication tokens to any Git worktree or branch. | Staging environment files or secrets in commits. |
| **G10**| **Path Portability** | No Swift source file, fixture, or unit test may contain hardcoded absolute paths tied to a local machine (`/Users/...`). | Hardcoding local machine paths in executable code. |

### 3.2 First-Class Accessibility (A11y)
- **VoiceOver Spoken Labels:** Monetary and statistical components must never allow screen readers to speak raw punctuation like `/` or `$`. Use:
  ```swif
  .accessibilityLabel("Hourly rate: \(rate) dollars per hour, estimated total \(total) dollars")
  ```
- **WCAG 2.2 AA / AAA Contrast Compliance:**
  - Light Mode: `primary700` (`#C63A17`) over `primary50` (`#FFF1EC`) $\to$ **5.8:1**.
  - Dark Mode: `primary400` (`#F26643`) over `primary500.opacity(0.18)` with 32% border $\to$ **6.4:1**.
  - Always consume `FrilaColor.dynamicBrandChipBg` and `FrilaColor.dynamicBrandChipText`.
  - Solid confirmed state (field or row filled after an intentional choice): `dynamicBrandSolidFill` (`primarySelection`, `#C9470F`, OKLCH 0.572 0.176 39.3) with white `dynamicBrandSolidText` in both modes $\to$ **4.78:1**. The brand is darkened just enough for white text and its hue is rotated 4 degrees toward yellow so it stays orange. Never darken along the brand hue (`primary600`, 35 degrees): it reads as red, an alert or error. Dark ink on the brand orange was also tried and rejected: the typography read as strange. Tests: `testBrandSolidFillWithItsTextClearsAA`.
  - Selection wash (the chosen row while a choice list is open, and the row under the finger): `dynamicSelectionWash`, never the brand color. Light `#EDEDEB` (1.12:1 over the card), Dark `#282826` (1.21:1). Text on it stays AA with margin: titles 15:1 and 13:1, details in `dynamicInkSecondary` 9.7:1 and 8.5:1 (the lighter muted gray would drop below 4.5:1). Test: `testSelectionWashKeepsTextInAA`.
- **Tactile Physics & Reduced Motion:**
  - Buttons utilize `HapticBounceButtonStyle` with `.scaleEffect(0.96)` on press powered by `.interpolatingSpring(stiffness: 350, damping: 25)`.
  - Mandatory compliance with `@Environment(\.accessibilityReduceMotion)`: when active, clamp scale to `1.0` and disable expansive spring animations.
- **Associated Skills:** `better-accessibility`, `accessibility`, `better-colors`, `oklch-skill`, `better-typography`, `emil-design-eng`, `make-interfaces-feel-better`.

### 3.2b Form Typography (Editorial Pair)
The job form uses `FrilaFormType`, the Design System editorial pair on the Minor Third scale. Bricolage Grotesque carries the voice: the section question (Bold 26, tracking -0.6, `.title`) and words chosen from a catalog (category, role, level: Bold 17, `.body`; an inferred value in Regular). SF Pro carries the structure: typed input and option rows (17, `.body`, never smaller on mobile), support under the question (15), field labels (Semibold 13, +0.1), details (13) and uppercase micro labels (Semibold 11, +0.8, natural case in code with `.textCase(.uppercase)`). Figures and money stay SF Pro. Apply with `.frilaType(spec, dynamic: true)` so every role follows Dynamic Type. Do not add sizes outside these five steps (26, 17, 15, 13, 11) to the form.

### 3.2c Grouped Pickers (Common Region)
Pickers that answer one decision (Categoria and Função) share one container via `groupStyle` (R 26 = field 14 + padding 12; fields keep `radiusInput` even with a wheel open). The goal is segregation, achieved differently per mode:
- **Light:** the group is a white card lifted off the canvas by `frilaGroupElevation` (Beautiful Shadows md: a 1 pt ring at 6% plus four neutral layers at y 1, 3, 6, 12). Fields inside are `groupFieldLight` (`#F6F6F4`) with an 8% hairline (`FrilaFieldChrome.cutout(stroke:)`). Near-gray containers side by side, without ring or lift, read as a low-fidelity prototype.
- **Dark:** soft tone steps (group `#1C1C1A`, field `#2A2A27`, lighter than the group), ring only, no shadow.
- **Confirmed:** selection orange with white text in light (4.78:1), graphite with white text in dark (8.9:1). Never absolute black.
Palettes: Grafite (default), Pedra (warm), Laranja (experimental). Labels sit on the field text column (14 pt in); the open/close affordance follows M13.

### 3.3 Mobile Anti-Patterns (Web Page Carryovers)
Frila is a mobile app. Patterns inherited from web page applications are defects, not style choices. Reviewers must reject them, and agents must not introduce them. Origin: add-role form review, 2026-10-01 (floating icon, ghost check and a bare "Cancelar" text inside a 150 pt sheet).

| # | Anti-pattern (web carryover) | Mobile rule |
| :--- | :--- | :--- |
| **M1** | **Text as button.** A bare centered word ("Cancelar", "Voltar") with no shape or fill as an action. | Every action is a Capsule pill (32/44/52 pt) through `FrilaPillButtonStyle`. Secondary actions are `.outline`, never plain text. |
| **M2** | **Icon-only submit inside a field.** A faint check or arrow circle at the field's trailing edge as the confirm control, disabled state shown as a ghost icon. | Confirm is a labeled primary pill ("Adicionar"). The keyboard return key (`.submitLabel(.done)`) also confirms. A disabled primary pill is dimmed, with the same shape and label. |
| **M3** | **Decorative leading icon.** A `plus.circle` or search glyph in front of a text field that carries no information. | Fields start with the text. Icons appear only when they change meaning (clear, status). |
| **M4** | **Chrome-less field.** Text typed on the bare surface with only a caret to say "type here". | A text field has its own surface, border and concentric radius (`R_field = R_container - padding`), plus an accent border when focused. |
| **M5** | **Free-floating controls in an oversized container.** Small controls scattered with large dead space, sizes unrelated to each other. | Controls fill the container width on a 12 pt rhythm. Paired actions share height and width. Field 44 pt, actions 44 pt. |
| **M6** | **Hover, tooltip or inline-link reliance.** Meaning that depends on hover, or links inside body text as primary navigation. | Touch has no hover. Use visible state, labels and 44 pt targets. |
| **M7** | **Wizard auto-advance on exploration.** Moving focus or opening the next field when a value merely settles (scroll wheel stop, partial input). | Advance only on an explicit commit (tap on the confirmed item, a Next or Done action). Settling is exploration. |
| **M8** | **Web-form layout.** Labels as placeholders only, tiny inline error text far from the field, modal dialogs for simple input. | Label above the field, error or hint directly below it, and inline expansion or a sheet instead of a dialog. |

Origin: "Experiência desejada", 2026-10-01. | One full-width row per option, in rank order, top to bottom. Each row shows the name and one line on what it asks; order carries the rank (no repeated glyph, see M11). Reference: `FrilaExperienceLevelPicker`. |
| **M10** | **Tinted chip-color surface as the "selected" state.** A pale brand wash (`dynamicBrandChipBg`) behind a whole field or row to mean "chosen". It reads as decoration, not state. | Confirmed state is either the accent border on a neutral surface or the solid brand fill (`dynamicBrandSolidFill` with `dynamicBrandSolidText`). Chip colors are for chips and badges only. |

If an icon is needed, each level gets its own distinct symbol with a reason to exist, or a single animated symbol tied to the selection. |

The section leaves vertical room so the user can bring the control to mid-screen. The chosen row is marked by the gray selection wash and a heavier name (Bricolage Bold; the other options Regular). The wash is a single layer behind every row, sliding on `FrilaMotion.selectionWashSlide` (Liquid Glass spring, 0.5 s, bounce 0.12); a wash per row draws over the text of the rows it crosses. The weight swaps without animation (a static font cross-fading two widths shows doubled text). No check while choosing. The choice is the conclusion: a tap, or the release of a slide, sets the value and collapses the list in the same transaction (no timer, no second tap to accept). The chevron then turns into a check for a moment (SF Symbol replace) with a success haptic. ### 3.4 The Six Anti-Slop Pillars (consolidated)
Every line of SwiftUI is reviewed against six pillars. Most of their content already lives in G1 to G10, section 3.2 and the M table. This section holds only what those do not say, and maps each pillar to where its rules live.

| Pillar | Where the rules live | Additional rules (not stated elsewhere) |
| :--- | :--- | :--- |
| **1. Copywriting & Tone** | G3, 3.2 | Concise *Artsy Museum Placard* register. **No middle dots or bullets (`·`, `•`) and no artificial dashes (` — `, `-`) as text glue.** Separate information by native structure (stacks, typography hierarchy, opacity contrast, chips) or by ordinary grammatical commas. No decorative glyphs in chips or badges, no generic AI marketing copy. |
| **2. Visuals & Depth** | G2, 2.2 | Media outlines are pure alpha: 8% black in Light, 10% white in Dark. No tinted gray or slate borders on photographic boundaries. |
| **3. Color & Contrast** | 3.2 | Colors come from `FrilaColor`, with no raw hex literals in views. Dark Mode shifts to `primary400` (`#F26643`). Never place `primary50` on a dark canvas (1.1:1). Chip surfaces and text consume `dynamicBrandChip*`. |
| **4. Typography & Numbers** | G4, G5, 3.2b | Upright Swiss standard through `FrilaTypography`. Hero prices and metrics use SF Pro with **proportional figures**. **Tabular numerals only** for animated tickers, sliders and histogram columns. Never SF Mono for prices. Metric ceilings: `metricMonumentalSpec` at 38 pt, `metricCardBigSpec` at 34 pt with condensed tracking (-0.035 em). |
| **5. Geometry & Touch** | G6, G7, G8 | Paired buttons and rows share the same height. |
| **6. Tactile Physics & Springs** | 3.2, 3.5 | Press bounce through `HapticBounceButtonStyle`. Reduce Motion locks the scale at 1.0. No linear or generic `easeInOut` for movement. Every motion choice is checked against the Motion Philosophy (3.5). |

### 3.4b Product Statement: Dissolve the Information
Whenever possible, hand the user information already resolved, in its most immediately readable form, instead of making them decode it. Full words over abbreviations ("Sexta-feira, 25 de setembro", not "Sex, 25/09"), relative references when they say more ("Amanhã"), computed results in evidence (contracted hours, totals) instead of raw inputs, and one field per line when squeezing would force abbreviation. This is a design priority on the same level as the visual pillars: if a layout only fits by compressing information, change the layout. Origin: shift date field, 2026-10-01.

### 3.5 Motion Philosophy (Tech Minimal, Apple-like, Liquid Glass)
**Rule of record:** whenever a task touches interface refinement (polish, transitions, expand/collapse, pickers, sheets, chips, any state change), the motion pattern must be re-evaluated against the current high-fidelity standard (latest Apple iOS 26 / Liquid Glass behavior and the newest approved Frila prototypes), not copied from what the component already does. Existing animation is a starting point, never the authority.

Learned principles (Picker, 2026-09-30):
1. **Disclosure is asymmetric.** Opening: a spring with almost no bounce (`FrilaMotion.disclosureExpand`, duration 0.42, bounce 0.08). Closing only settles: shorter and critically damped (`FrilaMotion.disclosureCollapse`, duration 0.32, bounce 0). Never reuse one curve for both directions. (Revised 2026-10-01: the earlier 0.46/0.78 spring read as too bouncy.)
2. **Bounce is small and bounded, and the container never pops up.** Bounce 0 to 0.1, overshoot of a few points (`disclosureOvershootAllowance`, 3 pt). Clamp the opposite side so undershoot never cuts content or shrinks a field below its closed size. Opening settles downward (`disclosureDropOffset`, 2.5 pt, no scale): a scale or upward lift anchored at the top reads as a pop-up. Corner radius morphs on its own Bézier (`disclosureMorphExpand`/`Collapse`, iOS drawer curve 0.32, 0.72, 0, 1), separate from the height spring, so the corner never overshoots.
3. **One owner for the morph.** Surface, border, shadow, corner radius and clip live on a single container (`FrilaMorphingFieldContainer`) so height, radius and mask animate together. Children are chromeless. A rectangular `.clipped()` over rounded content is a defect.
4. **Content cross-fades are staggered with ease curves.** Exit uses ease-in and is short (`contentFadeOut`, 0.09 s). Entry uses ease-out with a small delay (`contentFadeIn`) plus a tiny scale (0.98, top anchor). Two layers of text must never overlap. Opacity may use ease-in/ease-out. Movement and size use springs.
5. **Depth is subtle and continuous.** Cylindrical wheel projection (max 50 degrees), per-row blur growing with distance (max 2.4 pt), smoothstep edge masks. No banded blur, no linear two-stop fades.
6. **Reduce Motion flattens.** Springs become none, projection, tilt and blur turn off, crossfades stay instantaneous.
7. **Pending states live on the content, not on a replacement.** While a list waits (coupled picker friction), keep the real text legible and animate it: a diagonal specular sweep, an opacity breath and a light scale pulse on one shared phase (`FrilaPendingTextEffect`, 1.5 s cycle), chained across rows by a phase offset so the wave travels down the list. Intensity ramps in and out (no hard state swap). Show it only for perceptible waits (>= 0.15 s) so fast changes never flicker. Do not swap text for skeleton bars. Reduce Motion keeps only a static dim.
8. **Neutral slots are marks, not buttons.** An empty or "none" state is a discreet mark (a small capsule), never a label that reads as a tappable action.
9. **Collapse on choosing.** Expandable choices start collapsed, showing only the chosen content. The final interaction (a tap, or the release of a slide) sets the value and collapses the list at once with `disclosureCollapse`, so the minimum number of interactions concludes the step. No auto-dismiss timer and no separate accept action. Choice lists also accept a press-and-slide (hold about 0.15 s, then drag) so a choice costs one gesture.
10. **Text never swaps instantly.** Any text state change (weight, title, label, value) animates: staggered cross-fade, blurred cross-fade for a static font weight, a revealing mask, or `numericText`. Only Reduce Motion makes it instant (M15).
11. **Grow away from the thumb.** A floating card that changes height between steps is anchored at the bottom and grows upward: what is touched at every step (step list, confirm pill) stays fixed in the lower third, and only the top edge morphs (M17). An inner core that resizes inside a morphing card is clipped to its own slot so it never draws over its neighbors mid-morph.
12. **Swap heavy cores outside layout.** When a morphing container swaps a heavy core (a UIKit calendar or wheel), never swap it by identity inside the layout: the outgoing view holds the old size until its exit ends and the container retargets mid-spring (a visible stall), and the two cores overlap. Give the slot an explicit height per state, draw the cores as overlays, fade out on `contentFadeOut` and fade in only after it ends (`coreSwapFadeIn`), keep the width constant across states, and scope `.animation(value:)` to the property it owns so it never animates a text swap by accident.
13. **Tokens, not literals.** Every duration and spring lives in `FrilaMotion`. New motion adds a token with a doc comment, plus a test when it carries a numeric bound.
